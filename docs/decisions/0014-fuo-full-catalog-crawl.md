# Full FuOverflow catalog crawl (every subject, every thread kind)

- Context: the exam library only knew FE threads, imported by hand from a browser-extension export (`npm run import:fuo-catalog`). The owner wants the whole FuOverflow catalog (FE, PE, Quiz and anything else in every subject forum) kept on the server, and users able to fetch PE and Quiz threads too.
- Decision: an admin-started background run (`jobs/fuo-catalog.worker`, tables `fuo_catalog_runs` and `fuo_catalog_subjects`, same single-active-run shape as `fuo_source_runs`) reads the public subject index and then every page of every subject forum, sequentially, with the crawler's session/client and a pause between pages (`constants/fuo-catalog.ts`). It waits while a user crawl job or a "load new data" run is active. Only metadata is stored in `fuo_threads` (title, date, replies, raw label, `kind`); images and files are still fetched on demand by the importer. No automatic schedule.
- Kind: `classifyKind` uses the label first ("Đề Thi FE/PE", "Quiz"), then FE/PE/Quiz tokens in the title, else OTHER. `exams.kind` is set at import/refresh/merge; old exams are filled once at boot from the title (FE when the title says nothing, since they were all imported under the FE label).
- Importer: the FE-label requirement is gone. Protection kept for threads that are not exams: a thread whose breadcrumbs show it is outside the subject forums is refused (preflight and worker), and a thread without any image or attachment is still refused. PE threads are not sent to AI (images are the task statement, not multiple-choice questions). The first post is stored as plain text in `exams.description`.
- Writes: per subject, rows are diffed against the stored ones and only new or changed rows are written, in chunks, in one transaction with the run counters. Threads that disappear from FuOverflow are kept.
- Failure handling: a login/Cloudflare failure stops the run as `NEEDS_AUTH` and the subject goes back to the queue; the next start resumes the run. Any other failure is recorded on the subject and the run continues. An unreadable subject index ends the run as `FAILED`.
- Consequences: one full run costs one request per forum page (20 threads per page) plus the index page. Progress is pushed on `admin:fuo-catalog`; notices `catalog.done` / `catalog.failed`. The catalog API gains `kind` on items and an optional `kind` filter (additive).
