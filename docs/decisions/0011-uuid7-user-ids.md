# UUID v7 ids for users

- Context: `users.id` was the last auto-increment id visible to clients (admin URLs `/admin/users/12`, API payloads, JWT subject), leaking the number of accounts and making ids guessable. Decisions 0009 and 0010 already moved records with detail pages, exams and sessions to UUID v7.
- Decision: `users.id` is `CHAR(36)` UUID v7 (`@default(uuid(7))`). Every column holding a user id follows: 37 foreign keys (`user_id` of 34 tables, `users.referred_by_id`, `referral_rewards.referrer_id/referred_id`) and the soft references `admin_notices.user_id`, `chat_logs.user_id`, `crawl_jobs.user_id`, `exams.created_by_id`, `marketing_broadcasts.created_by_id`, `coursera_orders.credential_viewed_by`, `answer_reports.reviewed_by_id/resolved_by_id`, `explanation_feedback.resolved_by_id`. Other tables keep their int ids.
- Migration `0080_uuid7_user` follows 0079 (guard, mapping table, one `MODIFY` per table, `UPDATE ... JOIN`, FKs re-added with the same names). Ids are built from `created_at` plus the old id bits, so `ORDER BY id` still means sign-up order. Production data is kept; the header lists money and ownership checksums to compare before and after.
- Sessions: refresh tokens are converted in place, so nobody is logged out. Access tokens whose subject is not a UUID get 401 and the client renews them through the refresh cookie. Impersonation tokens carry the admin UUID in `imp`.
- Mail links already sent: marketing and reminder unsubscribe links carry the old numeric id under a valid signature. `userRepository.findIdByLegacyId` finds the user from the old id bits that 0080 keeps inside the UUID, so those links keep working. Click-tracking tokens use log ids (int) and are unaffected.
- Not affected: guest ids (own column), referral and deposit codes (random), avatar files (path stored in the row).
- API: every user id in params, query, body, responses and the JWT `sub` is a UUID string, validated with `uuidSchema` / `uuidParam`; old numeric ids get 422. Breaking change shipped in one step by owner decision: backend (API stopped during migrate) first, frontend right after.
